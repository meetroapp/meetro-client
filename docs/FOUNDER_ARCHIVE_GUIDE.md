# Founder Archive Protection Guide

## 1) Purpose

Meetro’s repository protects code, behavior, and product philosophy over time.  
The Founder Archive protects the historical journey and original discoveries that led to this product.

The repository is where the active project lives and is maintained.
The Founder Archive is where we preserve context, memory, and direction across phases and eras.

## 2) Repository Inheritance Structure

Use this order when aligning work:

1. **Vault**
2. **Constitution**
3. **KnowledgeBase**
4. **Architecture**
5. **Stewardship**
6. **Execution**
7. **Code**

The order is intentionally directional:

Vault → Constitution → KnowledgeBase → Architecture → Stewardship → Execution → Code

## 3) Vault Protection Rules

- The Vault protects Meetro’s immutable product DNA.
- Vault documents may only be amended by discovery, never by preference.
- The Vault is not implementation guidance.
- The Vault is not marketing copy.
- The Vault should not be copied into public materials without founder approval.

## 4) Founder Archive Recommendation

Recommended external structure:

- **Meetro Founder Archive/**

## 5) Preservation Protocol

Preserve each phase safely and redundantly:

1. Commit frontend.
2. Commit backend.
3. Push both repositories.
4. Create an external snapshot.
5. Tag milestones.
6. Keep offline/cloud backup.

## 6) Phase 5 Milestone

Phase 5 documentation and design introduced and stabilized:

- Persistent Context
- The Current Work
- Focus Workspace
- Work Center Attention Model
- Vault protection
- Documentation inheritance

## 7) Closing Principle

The professional never stopped working on the current work.  
The software should never behave as if they did.

The Vault protects the DNA.  
The Constitution protects the philosophy.  
The Founder Archive protects the journey.
