# Meetro Community Intellectual Property Ledger

This directory preserves a version-controlled record of Meetro Community inventions, proprietary systems, creative works, and brand candidates. Its purpose is to support chronology, authorship, ownership review, and informed protection decisions without publishing the confidential details that create commercial value.

Classification in these files is preliminary governance metadata, not a legal determination. Patentability, ownership, registration, clearance, and enforceability require review by qualified counsel.

## What To Record

Record major architecture milestones, technical problem statements, implemented solutions, product concepts, new intelligence engines, workflow systems, original documentation and designs, brand names, logos, public disclosures, contributors, repository paths, and verified commit evidence.

Do not record API keys, passwords, tokens, production credentials, full private prompts, customer information, private messages, payment credentials, production database details, undisclosed investor terms, exploitable security details, or the operative logic of a trade secret.

## Update Rhythm

Review the ledger after every qualifying milestone in the [IP Governance Standard](IP_GOVERNANCE_STANDARD.md), and at minimum before a public launch, investor disclosure, contractor handoff, patent discussion, or formal IP assignment.

## Adding An Entry

1. Complete the [Invention Disclosure Template](INVENTION_DISCLOSURE_TEMPLATE.md) using facts only.
2. Commit and test the implementation before calling it implemented.
3. Add the chronological entry to [IP_LEDGER.md](IP_LEDGER.md).
4. Record the exact commit hash and repository-relative evidence paths.
5. Classify the item preliminarily and record whether it has been publicly disclosed.
6. Add a governing reference to the appropriate specialized register.
7. Assign a legal, confidentiality, ownership, or evidence follow-up.

Git history supports chronology by preserving the committed content, author metadata, timestamp, and evolution of each entry. It supplements, but does not replace, signed assignments, invention declarations, public-disclosure records, or legal advice.

## Operational Classifications

- **Patent candidate:** A potentially protectable technical invention requiring novelty, prior-art, inventorship, disclosure-timing, and filing review.
- **Trade-secret candidate:** Valuable confidential know-how that depends on access controls and disciplined non-disclosure.
- **Copyright:** Original expression such as source code, documentation, graphics, interface designs, and product copy. Registration status must be recorded separately.
- **Trademark candidate:** A name, phrase, symbol, or logo that may identify source. Availability, priority, ownership, and registration require clearance and evidence.

Keep broadly accessible records descriptive but minimal. Store sensitive supporting material only in an approved restricted repository with access and retention controls.
