# Continuity Laws

These laws define the minimum continuity behavior for all surfaces and roles.

## Law One: Work is the Anchor

The work is the stable center.

Context must survive tool changes.

Tools must serve the current work, not redefine it.

## Law Two: Context Is Never Duplicated

Use one source of truth for identity, relationship state, lifecycle stage, and shared projections.

Professional and homeowner surfaces may project differently but must project the same work truth.

## Law Three: Focus Before Surface

Attention should move before surface changes.

The current work should feel coherent across schedule, evaluation, proposal, and closure stages.

## Law Four: Role-Safe Continuity

Role changes and mode switches must preserve work continuity while projecting correctly.

Continuity rules apply across Homeowner, Professional, and emergency pathways.

## Law Five: Continuity in Practice

- A work item cannot become two unrelated jobs.
- A request should not disappear when responsibility changes.
- A completed work should move to history without becoming unreachable truth.

## Enforcement

If a screen requires a behavior that competes with continuity, it is a design failure before code level.

Implementation can be iterated later.
Vault direction remains the constraint.
